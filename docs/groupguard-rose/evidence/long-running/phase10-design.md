# Phase 10 concrete federation enforcement

Extend Phase9's own bot UUIDs, composite constraints and owner/admin distinction. Private fban/unfban/stat/list/import/subscription commands always use actual PM ownership context, even with a connection. Groups use their attached federation. Group creator controls membership; owner controls directed subscriptions/list/import; owner/admin controls fban/unfban; all attributable humans can read scoped stats. Federation notifications and configured logs are separate from active per-group fanout, which is silent.

GuardFedBan(bot,fed,user) stores active intent, monotonically increasing version, reason/name/minimal username, by_id and actual dates. Keep inactive tombstone versions so old jobs cannot resurrect bans. GuardFedSub(bot,fed,target) has two composite FK constraints; no cross-bot/self edges. All graph writes serialize; reject cycles and locally bound outdegree32/reachable128 before committing, with explicit diagnostics. Directed A→B means A's groups enforce B's bans. Resolve a bounded graph with direct/subscribed provenance, never erase another source when one is removed. Graph changes invalidate current generations and enqueue bounded reconciliation for actually observed users. Deletion removes federation data and retires its local restriction source without Telegram unban; local manual unban may then act under ordinary current rights, retaining unrelated sources.

Use a separate GuardFedObservation(bot,chat,user,last_seen) populated only from actual human group messages and completed joins, not serialization sentinel rows or arbitrary moderation targets. No full member inventory, history crawl or user-account client. Group join/reassignment sees current direct/subscribed bans at the next actual observation; bounded existing observed users are reconciled through jobs. Only positive human observations; bot/sender_chat/private payloads do not become human inventory.

Fanout job versions carry source federation/user/ban version, actor and keyset cursor. Per-destination enforcement jobs capture attachment generation and relevant source versions but rederive current graph/active intent before dispatch. Use current namespace, active group, federation initiator role and exact bot restrict rights; current protected Telegram targets win over automatic enforcement. Acquire the federation intent row locks while dispatching, and make writes/deletion share these locks. Old ban RPC must finish before a newer unban intent commits; final fresh version guard runs after pending restriction evidence and immediately before RPC. Remote unknown completion order remains an explicit transport limit, never exactly-once certification.

Reuse durable GuardJob leases/claim/recovery/retry bounds and shared module outbound quota. Keep local quota waits outside API retry attempts. Expand in bounded100 batches, preserve fair cursor, cancel obsolete undispatched work. Known RetryAfter retries at most5; unknown dispatched outcome is uncertain without blind replay. Current committed federation security policy continues in passive checks even if its old issuer is later demoted; new active fanout from a revoked issuer is denied and recorded.

Passively enforce on actual joins/speaking before generic approval, raid, newbie or CAPTCHA; current protected Telegram admin remains exempt from automatic removal. Existing independent owned bans and optional CAS remain separate. Requests must not be approved through an issued verification when current fed policy bans that user. Unless quietfed, passive removal states the actual source federation and escaped reason; active fanout has no per-group notice/log. Separate owner notification/log records still describe federation ban changes.

Use source `fed:UUID` in GuardRestriction, with source ban version generation. A known applied RPC may prove joint federation policy owners for the same resulting permanent ban; unknown outcomes retain conservative ownership. Removing one owner retires only that source locally; remote unban occurs only for a known owned ban, current no-active-federation intent, no other live local ban and fresh current target/capability proof. Unknown ownership does not authorize release. An external administrator making an identical ban cannot be identified by Telegram's member DTO; document that observable limitation.
