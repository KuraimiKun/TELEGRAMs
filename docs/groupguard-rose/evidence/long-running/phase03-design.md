# Phase3 concrete implementation design

Source S08/S18–S21/S36–S39 and long-running addendum S37/S38 control this implementation. Single-word note names; quoted/parenthesized multiple filter triggers. Existing broad stored names/HTML/media remain readable as explicit legacy extension.

One content envelope: raw source plus format html/rose, attachment kind/file_id and parsed controls. Default existing rows html; new plain commands Rose, rich Telegram entities sliced with UTF16 offsets and serialized safely to HTML. Shared renderer produces sanitized HTML, actual button targets/rows and Telegram flags; fillings are inserted as escaped atoms after style parsing. Code/literal escaping, nested styles, ordinary/expandable quotes, URL and note buttons, same-row, random%%% and documented controls have dedicated cases. URL schemes/keyboard/body/caption limits are validated. Unsupported media flags are explicit errors.

Add GuardItem format/options and bot-scoped GuardRepeat cadence/generation/author/next-run state through additive migration0012; preserve existing text/media/keys/unknown config. Extend frozen Operation to carry validated format/options and add owner-only clearall. Repeat/repeated aliases parse durations; changes/deletes cancel old generations. Sweep claims durable jobs, checks current item/version/author+bot rights, marks dispatch before API and advances cadence with one bounded catch-up. Paused contexts retain/cancel appropriate work under1C contracts.

Common delivery handles all supported attachments and text consistently, applying nonotif/protect/preview/media spoiler/reply/fillings. Sticker/video-note text companions are explicit steps. Menu bindings use a separate content slot so CAPTCHA/settings bindings cannot overwrite them; actual bot/message/chat/thread binds opaque targets. Group/PM note/rules reads recheck current membership/admin access. Private links store bot/group/item tokens and never grant write authority. No arbitrary username resolution or cross-tenant menu state.

Replace rules/save/get/filter/greeting handlers with this shared delivery. Rules private/custom button/reset and fillings; welcome/goodbye bool/text/media/preview/noformat/reset; durable five-minute old-welcome cleanup distinct from service cleanup. New greeting configuration uses envelope fields while legacy welcome_text/rules remain readable. CAPTCHA media greetings preserve the actual verification prompt/generation; nonbutton CAPTCHA expansion stays4.

Filter grammar supports quoted phrases and parenthesized comma-separated triggers, prefix/exact, replytag, admin/user/bot controls. Clone command suggestions validate actual Telegram command rules (1..32 lowercase Latin/digits/underscore, documented page fewer-than32 difference disclosed), publish/remove in correct chat scope through real SetMyCommands/DeleteMyCommands with rollback/failure evidence. Bot triggers default off, allow_bot opt-in; own bot never triggers itself. Functional /button helper provides copyable markup plus working preview.

Gate: renderer malformed/escape/nested/RTL/Unicode/entity/length/hiddenURL/control/button cases; every supported attachment; preview versus delivery; privileged note/filter contexts; callback/PM failure and forged scope; shared SQL legacy migration; real cadence/restart/change/delete/cancellation/author revocation; standalone and actual child dispatchers; focused/static/real-service/schema/runtime gates. Never mark a schedule/selector as functional without actual job delivery.
