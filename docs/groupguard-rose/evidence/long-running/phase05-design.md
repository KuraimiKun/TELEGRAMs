S22 roster and allowlist contracts require actual message/edited/event enforcement. Keep legacy links/invites/forwards/media/stickers/gifs/voice/polls/bots readable as explicit aliases; canonical roster all,album,anonchannel,audio,bot,button,cashtag,checklist,cjk,command,comment,contact,cyrillic,document,email,emoji,emojicustom,emojigame,emojionly,externalreply,forward,forwarduser,forwardbot,forwardchannel,forwardstory,game,gif,guestbot,inline,invitelink,botlink,location,outsidereaction,phone,photo,poll,reaction,rtl,spoiler,sticker,stickeranimated,stickerpremium,text,url,video,videonote,voice,zalgo. Expand all into canonical configured types and retain no-lock default. Actual SDK Message fields include guest_bot_caller_user/guest_bot_caller_chat, checklist, paid_media, forward_origin, sender_chat, via_bot, external_reply, reply_to_story, entities/caption_entities and sticker.premium_animation. Avoid nonexistent field inference.

Pure bounded detector returns typed evidence per violation, including visible/hidden entity URLs, keyboard URL/button, Unicode script/RTL/emoji/combining sequences, album/media/origin/inline/guest/message fields. UTF16 entity extraction preserves hidden links. Remote sticker/custom emoji pack lookup is bounded/cached and only used for relevant allowlists. Canonical media categories distinct from legacy broad alias behavior. Emoji detection uses current Unicode ranges/ZWJ/variation/tag handling with documented local matcher limit; emojionly requires text containing only emoji/whitespace, not a general symbol guess. Unattributed sender channels may delete-only; no invented human sanction target. Anonymous same-group sender-chat remains distinct from externally sent channel posts.

Typed allowlist entries distinguish URL domain/subdomain/path, exact private invite, public chat/bot/channel identity, command, pack and forward origin. Boundary-safe URL matching and query/credentials/hidden targets do not permit prefix bypass. A domain exception exempts only that target/evidence, not an unrelated prohibited URL or media in the same message. Keep unknown/unresolvable invite links nonmatching rather than fabricate membership lookup. Reply shortcuts derive actual sticker set/custom emoji set from verified SDK object/API receipt.

Per-lock mode/reason/options require validated grammar `type ... ### reason {mode [duration]}` with current change-info operation, lockwarns on/off, configured action/delete/warn actual outcomes and fresh union of capabilities. Creator-only clearing all allowlist. Public locks/locks list/locktypes show actual configuration and inventory; per-lock list descriptions and translated UI/help Phase11. Lock enforcement before blocklists; admins and scoped approved users exempt (independent manual/fed/night holds not weakened). Run edited messages without flood recount. Deterministic precedence when multiple lock policies hit: explicit severe action order, at most one primary sanction/warning and delete once, private evidence of matched types; document choice because digest does not fully order conflicting policies.

Reaction updates use actual MessageReactionUpdated/CountUpdated observers and replay identities. SDK3.31 installed DeleteMessageReaction(chat_id,message_id,user_id|actor_chat_id) and DeleteAllMessageReactions(chat_id,user_id|actor_chat_id) are real methods requiring can_delete_messages; SDK docs inspected locally, deployed server not verified. Revalidate reacting user's membership for outsider policy, admins exempt. Actor-chat can remove reaction by actual actor_chat_id but never sanction a fictional human. Anonymous aggregate events have no actor; acknowledge limits, do not infer a user. Unsupported deployed API returns explicit type/diagnostic/log outcome, no forged success or deployment certificate. Same update/message reaction version must not double warn/delete. One reaction removal actual API plus configured actor-aware policy where safe.

Gate each typed roster in text/entity/media/origin/event fixtures, admin/approval rights and delete/restrict union, independent allowlist boundaries and mixed targets, exact invite/pack/command/channel identities, message+edit/flood separation, ordinary/anonymous/nonmember reactions with actual removal API/unsupported response, standalone/two actual children, field/source ambiguities explicit.
