# Actual Group Guard API contracts

Phase1A checkpoint; later-stage changes are appended with migrations/state ordering.


- `contracts.Actor(bot_id, source_chat_id, kind, human_id=None, sender_chat_id=None, message_id=None, thread_id=None)` is frozen. `ActorKind` is human / anonymous_group / channel / bot / unknown / internal. Target chat is separately held by `Operation.target_chat_id`; PM message chat is independently bound. `authz.actor_from_message(ctx, message)` prioritizes sender-chat; only a group sending as itself is anonymous-group eligible. Neither pseudo-user nor sender-chat becomes creator. Bot-admin commands remain denied; internal automated entry points have no human authority.
- `contracts.Right` includes change_info, delete_messages, restrict_members, pin_messages, invite_users, promote_members, manage_topics, creator, plus post_messages for log-channel capability. `perms.Rights` retains short restrict/delete/pin/invite/promote/post fields and new topic/creator fields. `allows(right)` and `allows_all(frozenset)` normalize aliases, deny unknown rights and default missing old-cache fields false. Promotion/topic commands were not added.
- `authz.authorize(ctx, actor, *, target_chat_id, caller_rights: frozenset[Right], bot_rights: frozenset[Right]) -> Authorization`: uncached GetChatMember bot lookup, then actual human lookup. `Authorization.allowed/code/human_id/missing` are explicit; bool raises. Unattributed/wrong scope, lookup uncertainty, non-admin bot, missing bot/caller rights deny. Creator requires actual current human owner. Factory ownership, platform administration and admin display cache grant nothing. `internal_authorize(ctx, chat_id, required) -> Authorization` checks negative group scope and current bot rights only; its owning flow reads current policy.
- `perms.fresh_member` validates returned ID and catches expected Telegram API failures as unknown; `fresh_rights` converts current membership. `admins` retains a 300-second display-only cache. Manual and protected-target authorization do not consult it.
- `perms.resolve_target(ctx, message, args: str | list[str]) -> Target | None` or `TargetError`: reply precedence rejects sender-chat/bots; first-argument text_mention respects UTF-16 entity span; observed username cache requires an unambiguous observed ID plus fresh matching Telegram username/human; numeric IDs must satisfy `0 < id < 2**52`, exclude pseudo IDs 1087968824/136817688 and this bot. Unknown/stale/ambiguous usernames and negative IDs are rejected. No arbitrary username lookup/guessing. `Target.remaining` preserves the first reason token and internal spaces; `target_error` freshly denies bot/creator/admin targets and lookup uncertainty. Reply/entity/ID targets are protected immediately before execution. `/id` remains a separate chat-ID read path. Intentional automated bot-join enforcement stays separate.
- `perms.DurationResult.kind/value/error` explicitly distinguishes absent/valid/invalid. `parse_action_duration(token, *, required=False)` applies **60 seconds–365 days inclusive**, an approved local safety policy. `split_action_args(args, *, temporary_required=False)` treats digit/sign/dot-leading first arguments as time-shaped, rejecting invalid numeric/unit input; ordinary word `spam` is a permanent reason. `/tban` and `/tmute` require a valid timer after the target (or after the command for reply targets). Ordinary `spam 2026` remains a reason. General `parse_duration` is separate and accepts 10s; configuration/defaults were not rewritten.
- `operations.Operation` is frozen Pydantic, extra fields forbidden, with allowlisted existing kinds ban/mute/kick/unban/unmute/warn/unwarn/resetwarns/purge/delete/pin/unpin/setlog/unsetlog/config/save/remove/panel. It binds source/target chat, original message/thread/title, target ID/name, reason, relative timer, silent flag, reply/deletion IDs, validated JSON config patch, localized confirmation arguments, note/filter data and log destination. `rights()` returns complete caller/bot sets. `operation_for`, `submit`, `operation_authorization`, `execute(ctx, actor, op, *, reviewed=False, original_actor='human')` share direct and reviewed execution. Fresh config/title work precedes final authorization; reviews authorize again after claim. Reasons over the existing 256-character persistence limit are rejected, not truncated; output escapes HTML.
- `contracts.StepResult(operation, status, error_code=None, retry_after=None)` has applied/acknowledged/failed/skipped and `.completed`. `ActionResult(status, steps, primary_completed, requested_message_ids=(), acknowledged_message_ids=(), confirmed_deleted_count=None)` has applied/partial/failed/noop and `.with_steps`. Both bool conversions raise. `result_of` computes explicit primary completion. Completion means Bot API acceptance, not independently observed Telegram state.
- `actions.perform` catches TelegramAPIError and RetryAfter into sanitized type/code/delay; false/None API responses fail. Cancellation and programming failures propagate. `punish(ctx, chat_id, user_id, action, duration, *, origin='internal', absolute=None) -> ActionResult` denies unknown actions and current missing bot restrict capability. Kick completes only if ban AND unban complete. `sanction_deadline` computes ceil(now + relative seconds) immediately before API dispatch; absolute datetime/integer needs at least 45 seconds remaining and at most 365 days plus integer allowance. Expired/unsafe deadlines reach no timed API. Arbitrary network delay or Telegram changes between RPCs cannot be proved impossible.
- `unmute` uses `default_permissions -> PermissionResult(permissions | None, step)` with actual available defaults. Missing/empty defaults do not grant OPEN. `unban`, `delete`, `delete_many` return typed outcomes; batches are at most 100 IDs (single deletes individually acknowledged). Requested IDs, acknowledged IDs and partial batch failure are recorded; confirmed deletion count always remains unknown. Notifications, `log_event`, panel edits and review edits have separate typed ancillary evidence. Silent actions suppress normal public notices while retaining private operation/step evidence.
- `GuardService.config(chat_id, *, fresh=False)` preserves the 30-second read cache; protected execution/policy paths use fresh=True. No general config transaction/version redesign. `apply_warn(..., *, ancillary_steps=()) -> ActionResult`: bot restrict preflight before warning write; sequential threshold history resets only after intended sanction primary completion. Logging failure may produce partial aggregate while allowing that reset. Concurrent thresholds/latest-warning removal remain uncoordinated.

## Redis, attribution and scope

- `ctx.keys('gg','review',nonce)`: opaque 16-byte random token rendered as 22 URL-safe characters; TTL at most 120 seconds. Version1 JSON binds bot_id/source_chat_id/target_chat_id/original_message_id/review_message_id/thread_id/owner_id/created/expires/serialized immutable operation/SHA256 digest/required caller+bot rights. Large content is displayed in escaped same-thread chunks before the approval summary. Callback supplies only nonce and verified scope, never replacement operation arguments.
- Approval verifies actual callback human, sending bot, group/message/thread, callback group/user fields, version/digest/rights/creation/expiry and known owner if any; fresh bot/caller and protected target checks precede claim. Invalid or underprivileged clicks do not consume. Lua atomically compares the exact loaded payload and deletes it once. After claim, execute rechecks current authority; permission loss/API failure leaves the request consumed. Redis uncertainty denies. Forty concurrent real-Redis approvals produced one sanction; eight fake-Redis approvals did likewise across standalone/child test variants.
- Anonymous owner_id=None permits any currently sufficiently privileged human. Known-human requests bind that initiating ID. The approving human acts under their own rights; the original anonymous human remains unknowable. Public notices omit reviewer identity; no pseudo-user DM. Existing private AdminAuditLog records actual reviewer, actual original actor kind, normalized operation (including target/reason/silent deletions), primary completion and step statuses. Panel/review edit failures retain separate private ancillary evidence. The existing SQL audit sink is best-effort and logs its own storage failures.
- `ctx.keys('gg','panel',message_chat_id,message_id)` stores bot_id/target_chat_id/owner_id/message_chat_id/message_id/thread_id/kind/data for 3600s. Settings PM target is the bound group, never the PM chat. Warning/CAPTCHA/join-request kinds bind the relevant target/applicant. Private settings require PM chat==human; Telegram join-request user_chat_id may be its short-lived private contact and relies on server-created owner/message binding. Wrong user/bot/chat/thread/message/target and unbound callbacks deny. CAPTCHA binding does not add an issuance-generation fence; an old legitimately bound generation can still race a later one.
- Existing observed username key `ctx.keys('uname', lower_username)` retains 30-day TTL. New JSON {id, username, ambiguous}; old numeric records readable. Conflicting observed IDs become ambiguous; every username resolution checks fresh actual username. Namespace includes standalone slug or factory c<bot-id>; actual ChildRegistry children 710011 and 710012 shared the same group and could not read/use one another's review/panel/cache state.
- Existing night_closed snapshot TTL86400 and CAPTCHA pending/due keys remain. Atomic review claim is one-use cross-worker authorization, **not durable exactly-once Telegram delivery**; process death after claim can lose the action. No new table, durable inbox, lease or generation ownership was introduced.
